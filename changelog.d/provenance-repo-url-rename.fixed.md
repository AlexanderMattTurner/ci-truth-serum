- `check-provenance-repo-url` no longer fails a clone of a repository that was renamed. It now identifies the publishing repository from `$GITHUB_REPOSITORY` first, because npm mints the provenance bundle from that variable, and falls back to the `origin` remote. A rename redirects the old URL, but every existing clone keeps that URL in `origin`, so the check used to report a manifest that already carried the new name. The check now follows the redirect with `git ls-remote` and accepts the name it lands on. That is the only network call, it runs at most once per repository, and it runs only after a mismatch, so a clean repository stays fully local. A repository with no `origin` remote is still judged when `$GITHUB_REPOSITORY` names it.
