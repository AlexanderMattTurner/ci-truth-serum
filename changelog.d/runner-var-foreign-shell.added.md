- `check-runner-var-foreign-shell` (Tier 1, honesty): flags a workflow or composite-action step that reads `GITHUB_OUTPUT`, `GITHUB_ENV`, `GITHUB_PATH` or `GITHUB_STEP_SUMMARY` under a shell GitHub does not set up. Each of those variables holds the path of a file on the runner, and the runner reads that file after the step ends. A shell such as `docker run … {0}` runs the script in another filesystem, where the path is absent, so the write reaches nothing and the step still exits 0 with an empty result. The check reads the effective shell from the YAML — the step's own `shell:`, else the job's `defaults.run.shell`, else the workflow's — so a `shell:` inside a comment is not one. `bash`, `sh`, `pwsh`, `powershell`, `python` and `cmd` are clean, and so is a custom template that re-invokes one of them, such as `bash -e {0}`. Opt a step out with `# allow-runner-var-foreign-shell: <reason>`.
