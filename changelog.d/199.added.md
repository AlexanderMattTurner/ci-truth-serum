- `check-collapsing-job-group`: a new Tier 2 lint. It fails a job whose `concurrency.group` names a per-ref key that holds no value on one of the workflow's own events. GitHub leaves `github.head_ref` and the pull-request number empty off a pull-request event, and pins `github.ref` to the default branch on `schedule`, `workflow_run` and `pull_request_target`. The group is then one fixed string, so every run of that event shares one slot and cancels a run that tested an unrelated commit. The lint reports only when the job's own `if:` still admits that event, because a skipped job claims no slot. It reads the `if:` one-sided: a term it cannot classify restricts nothing, so a job gated through a `needs.<gate>.outputs` value reads as admitting every event. A group with no per-ref key stays out of scope, because moving a static workflow-level group down onto the expensive job is the remedy `check-static-concurrency` prescribes. Opt out with `# inert-group-ok: <reason>` on the job's key line or in its body.
- `check-static-concurrency`, `check-cancellable-required-check` and `check-pending-cancel-concurrency`: a per-ref key name written inside a quoted string literal no longer counts as a reference to that context. `${{ 'github.ref' }}` is the fixed text `github.ref`, so the group it builds is static.
