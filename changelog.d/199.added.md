- `check-collapsing-job-group`: a new Tier 2 lint. It fails a job whose `concurrency.group` names a per-ref key that holds no value on one of the workflow's own events. GitHub leaves `github.head_ref` and the pull-request number empty off a pull-request event, and pins `github.ref` to the default branch on `schedule`, `workflow_run` and `pull_request_target`. The group is then one fixed string, so every run of that event shares one slot and cancels a run that tested an unrelated commit. The lint reports only when the job's own `if:` still admits that event, because a skipped job claims no slot. It reads the `if:` one-sided: a term it cannot classify restricts nothing, so a job gated through a `needs.<gate>.outputs` value reads as admitting every event. A group with no per-ref key stays out of scope, because moving a static workflow-level group down onto the expensive job is the remedy `check-static-concurrency` prescribes. Opt out with `# collapsing-group-ok: <reason>` on the job's key line or in its body.
- `check-static-concurrency`, `check-cancellable-required-check` and `check-pending-cancel-concurrency`: a per-ref key name written inside a quoted string literal no longer counts as a reference to that context. `${{ 'github.ref' }}` is the fixed text `github.ref`, so the group it builds is static.
- `check-pending-cancel-concurrency`: the hook now also fails a job whose concurrency group holds one value across a trigger the job serves and a trigger it skips. GitHub claims a job's slot when it creates the job, before it reads the job's `if:`, so a run that skips the job still takes the slot and evicts the member already queued there — a live run's real work on a commit nothing superseded. `cancel-in-progress` does not change this, and the victim reports `cancelled` with every step completed and successful, so no log names a failure. This arm needs neither a `pull_request` activity type outside the defaults nor a required check, which the older arm both require. Fix a finding by ending the group `-shared` on the triggers the job serves and `-inert-${{ github.run_id }}` on the triggers it skips; write the first half as a non-empty string, because GitHub reads `''` as false. Opt out per job with `# inert-group-ok: <reason>`.
- Nine jobs in this repository's own workflows carried that shape and now vary their group by the same condition their `if:` reads.
