- `check-replacement-expansion`: a new Extras lint that bans an assembled string in a replacement position. `String.replace`/`replaceAll` and `re.sub`/`re.subn` read the replacement as a pattern before they insert it. JavaScript expands `$$`, `$&`, `` $` ``, `$'` and `$1`; Python expands `\1` and `\g<name>`. A literal stays clean, because the author reads every character of it. A template literal with a hole, an f-string, a concatenation, or a name this file binds to one of those is reported. The remedy is a function replacer, which inserts its return value verbatim. Both languages are read with their own grammar — `_js_ast` and `_py_ast` — so the idiom inside a comment or a string literal is not a finding. Opt out with `allow-replacement-expansion: <reason>`.
