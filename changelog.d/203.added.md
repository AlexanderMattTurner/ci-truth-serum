- `check-secondary-checkout-imports`: a new Tier 2 lint. It fails a job that checks out a second tree with `actions/checkout` `path:`, runs a JavaScript or TypeScript file out of that tree, and installs no Node dependencies anywhere in the job, when that file carries a bare import. The second tree has no `node_modules`, so the import is `ERR_MODULE_NOT_FOUND` on the runner and nowhere else. The lint reads the `run:` body through the bash grammar, follows one shell hop (`bash dir/x.sh` whose script runs `node …`), and reads the imports through the ECMAScript grammar. It also reads the tracked siblings the file relative-imports, one level down. A `require()` argument counts as an import. The runner decides which specifiers need a package: deno resolves `npm:`, `jsr:` and a URL by itself, bun resolves `bun:`, and a TypeScript type-only import is erased before any runtime resolves it. A step's `working-directory`, and the `defaults.run.working-directory` of its job or of the workflow, move where a relative operand starts. A step with `if: false` never runs, so the lint drops it. A job with `npm ci`, `pnpm install`, `yarn`, `bun install`, `actions/setup-node`, `pnpm/action-setup` or `oven-sh/setup-bun` is out of scope, including when a package-manager option sits before the install verb (`npm --prefix _ci ci`). A shell entrypoint the bash grammar cannot read is reported, never passed. Opt out with `# allow-secondary-checkout-import: <reason>` on the step that runs the script or on the checkout step.
- `check-relative-imports`: `specifiers()` now returns every static specifier of a file, `runtime_specifiers()` drops the TypeScript type-only ones, `require_specifiers()` returns the static `require()` arguments, and `relative_specifiers()` filters `specifiers()`. The hook's own verdicts do not change.
