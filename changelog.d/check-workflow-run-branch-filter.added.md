- `check-workflow-run-branch-filter` (Extras): reports a `workflow_run` listener with no `branches:` or `branches-ignore:` filter. GitHub creates a run for every completion of every watched workflow, on every branch, and the listener's own `if:` runs after the run exists. A run whose jobs all skip therefore costs the same run-creation path as a real one: about 3,000 such no-op runs sat `in_progress` at once, GitHub stopped dispatching `merge_group` check runs for about 7 hours, and the merge queue merged nothing in that window. Every one of those runs reported success. The check also reports a filter that narrows nothing (`branches: ['**']`, an empty list under either key) and the bare-name spelling `on: [workflow_run]`, which can carry no filter. Opt out with `# unfiltered-listener-ok: <reason>` on the `workflow_run:` key line or a direct-child line; the reason is mandatory, and a placeholder such as "n/a" fails.
