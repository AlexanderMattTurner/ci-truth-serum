- `check-uncached-download` now reads a cache key or path that holds an expression. Before this change, a key with a step output or an input made the whole job exempt, and so did a setup action's own cache. On agent-glovebox, that exempted 158 of 312 jobs. The check now resolves a composite action's `inputs.*`, `format()`, `hashFiles()` and a cache step's `cache-primary-key`. It also reads a step output that a `run:` script writes as `NAME=VALUE`, and `env.*` in a path. An expression that the check cannot read in a key still covers every download in the job. A part of a path that the check cannot read matches any directory.
- A setup action's cache now covers only the installs of its own installer. For example, `setup-node` with `cache: npm` does not cover a `pip install`. A cache whose path holds an installer's store, such as `~/.cache/pip` or `~/.npm`, covers the installs of that installer.
- A cache now also covers a download when its path holds a copy that a later `cp`, `install` or `mv` makes, or an absolute path that the step gives to a downloader function. A `hashFiles()` key now names a pin that the run reads from that file, for example `$(jq -r .version pins/tool.json)`.
- `check-uncached-download` now reads the pinned specs that an array holds, for example `pip install "${specs[@]}"`. An element that a condition or a loop adds is not counted.
