- `check-truncating-pr-json`, `check-versionless-install`, `check-pinned-downloads`, `check-gh-slurp-jq`, `check-stderr-merge-parse`, `check-echo-fallback`, `check-flag-arity`, `check-dead-shell-functions` and `check-test-predicate-shadow` now refuse a shell file that the bash grammar cannot parse, and exit 1. Before this fix, they reported that file as clean.
- The shell lints that read workflow `run:` scripts now refuse a workflow that PyYAML cannot parse, and exit 1. Before this fix, they read no script and exited 0. They also read only the scripts that bash runs, so a step with `shell: pwsh` is not read as bash.
- `check-pinned-downloads` and `check-versionless-install` now select files by type. So they also read a shell script that has a shebang and no `.sh` suffix.
- `check-frozen-head-sha`, `check-secondary-checkout-imports` and `check-sparse-checkout-closure` now agree on which step is `actions/checkout`. Before this fix, `./.github/actions/checkout-cache` or `actions/checkout-cache` counted as the checkout step.
- The shell lints that read workflow `run:` scripts now read only the steps GitHub runs: `jobs.<id>.steps[*].run` and the steps of a composite action. A `run` key under `env:` or `with:` is data, so it no longer gives a finding. A step that two jobs share through a YAML alias is now read once for each job, with the shell of that job.
