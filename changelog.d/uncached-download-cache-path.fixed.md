`check-uncached-download` now finds a pinned download that a cache in the job could not skip. A cache covers a download only when its step runs before the step that downloads, because a restore after the download cannot skip it. A cache key that names the pin covers a download only when one of the cache paths can hold the file that the download writes. The check compares only the leading path parts that the text fixes. An installer such as `uv tool install` keeps coverage by its key alone, because its own settings say where it writes. A `${X:-default}` reads as unknown when the `env:` of the step, the job or the workflow sets `X`. The check also reads a URL that a variable holds: a URL with a version that the text fixes is pinned, and a loop over mirror hosts (`for base in "${bases[@]}"`) reads as its first host. A function that declares a variable `local` reads only its own assignments of that variable.
