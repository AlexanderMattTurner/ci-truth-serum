- A shell file the bash grammar cannot read no longer reports clean. tree-sitter does not raise on malformed input — it recovers into error nodes and continues — and that recovery is not local in effect: one construct it cannot read drops the nodes a detector matches on for the rest of the file. Every grammar-based check therefore returned an empty result for a file it never really read, which is the same result it returns for a file it read and found clean. Measured with `check-exit-suppression`: a single `${x%%]*}` on line 2 hid a `|| true` on line 3 that the same check reports on line 3 of an otherwise identical file. The whole-file path now refuses such a file by name and line, and names the rewrite. `parse` itself stays permissive, because the workflow checks legitimately hand it `run:` blocks that carry `${{ … }}` — GitHub Actions syntax, not bash.
