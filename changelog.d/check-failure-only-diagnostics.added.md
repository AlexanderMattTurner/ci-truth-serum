- `check-failure-only-diagnostics` (Tier 2): reports a diagnostics step that GitHub skips on the run it exists to explain. A job that passes its `timeout-minutes` ends **cancelled**, not failed, and so does a job a `concurrency:` group supersedes or a human stops. `failure()` is false on all three, so an artifact upload or a log-collection script gated `if: failure()` reads “skipped” and the evidence dies with the runner. The check asks the step, or the job that holds it, to name cancellation with `always()` or `cancelled()`; a negated mention does not count, because `failure() && !cancelled()` still cannot run on a cancel. It flags an upload-artifact step, a `run:` body that calls a script such as `collect-logs.sh`, and a local composite action that holds either one. The body is read on the bash grammar, and the check reads the program a command runs rather than every argument, so a script name inside a printed message, or in `rm ci/collect-logs.sh`, is not a call. Opt out per step with `# failure-only-diagnostics-ok: <reason>`.
