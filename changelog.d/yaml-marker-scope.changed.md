- A marker in a workflow now sits in one of two places, and the same two for every check: a real YAML comment, or a `run:` value. GitHub hands a `run:` value to a shell, where a `#` opens the script's own comment, so an author may write the marker beside the line it is about. A `#` in any other value is content the workflow's own author writes, and it marks nothing.
- A `run:` value carries a marker in every style it is written in. The first spelling of this rule asked whether the value was a block scalar (`|` or `>`), which was wrong both ways: it lost a marker in `run: 'git diff  # frozen-head-ok: why'`, and it read one out of a `description: |` body and an `if: >` body, neither of which reaches a shell.
- `check-path-gate-deps` reads a `# gate-deps:` declaration only from a real YAML comment. That marker ADDS a path the check then proves is covered, so a path a step merely PRINTS would report a gate as complete that is not. Its sibling `# path-gate-ok:` only removes a finding, so it is still read from a `run:` script too.
- `check-pin-comment-truth` no longer reads a `#` glued straight onto the SHA. YAML calls `uses: owner/action@<sha>#v4` one value with no comment in it, so the `v4` there is neither a version claim nor an opt-out. Put a space before the `#` to get the comment back.
- `check-externalized-markers` reads a composite action's manifest as YAML. An opt-out in `action.yml` must sit in a real comment or in a `run:` value. A `.sh` source is still read as written, because every `#` in a script opens a comment.
