- `check-untrusted-exec` (Tier 1 · Security, default-on, included in `check-tier1`): fails a job that checks out a pull-request head and then executes code resolved from that checkout — a local composite action (`uses: ./…`), a package-manager script (`pnpm <script>` / `npm run …` / `yarn …` / `npx …` / `make …`), or a workspace-relative path (`bash ./scripts/x.sh`) — while any secret is live in the job. Reaches heads `check-trusted-base` cannot see (a matrix-derived `head_ref`, an unpinned `workflow_run` head) and is deliberately NOT silenced by `# trusted-base-ok`, so it audits that opt-out's usual "only runs the trusted base copy" claim. Opt out per job with `# untrusted-exec-ok: <reason>`.
