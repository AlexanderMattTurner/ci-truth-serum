- `check-uncached-download` (Tier 2): reports a job that downloads a version-pinned tool and holds no cache. The pin makes the bytes identical on every run, so each push to each pull request pays for the same fetch, and a slow registry turns that cost into a job timeout GitHub reports as “cancelled”. Local composite actions are inlined first, so a job that caches through a shared setup action counts as cached. Anything with no stable cache key is left alone: an unpinned install belongs to `check-versionless-install`, and a URL built from the runner's own `$GITHUB_SHA` or `$GITHUB_REF_NAME` names a different object on every run. Opt out with `# cache-exempt: <reason>`.
