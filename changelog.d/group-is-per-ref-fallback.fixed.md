- `check-static-concurrency` and `check-cancellable-required-check` now ask whether a concurrency group's per-ref key holds a value on each event the workflow declares, instead of looking for the key's name anywhere in the group. `github.head_ref` is empty off a pull request, and `github.ref` is the default branch on an event that carries no ref of its own (`workflow_run`, `issue_comment`, `schedule`), so the house group `${{ github.workflow }}-${{ github.head_ref || github.ref }}` collapses to one static string that every run of such an event shares. Both lints passed that group before. A key that keeps a distinct value on every declared event still passes, and so does an operand the lints cannot classify, an expression that is not a plain `||` chain, and an event outside the table. The message names the event that flattens the group.
