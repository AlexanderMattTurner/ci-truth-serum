- **`check-unbounded-waits`** now also fires on a runtime `exec` call in the condition of a `while` or `until` loop, such as `until docker exec c true; do sleep 1; done`. One probe against a wedged runtime never returns, so the loop never tests its condition again. The built-in tools are `docker`, `docker-compose`, `podman`, `nerdctl`, `kubectl`, `sbx`, `lxc` and `incus`. Add another with `--exec-tool NAME`. The check reads the condition through the bash grammar, so it also finds the call under `!`, in an `&&`/`||` list, in a pipeline, inside `$(…)`, and after a `compose` or `container` group word. A `timeout` or a registered `--bounding-wrapper` before the tool bounds each probe, not the loop. `# allow-unbounded: <reason>` opts a call out. The check now compares tool and wrapper words by basename, so `/usr/bin/timeout` bounds a call. An `exec` call outside a loop condition stays out of scope, and so does one inside a function that the condition calls.
