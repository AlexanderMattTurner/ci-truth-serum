- `_cts_linecheck` now owns four helpers two workflow lints had each encoded on their own. `default_run_shell` reads GitHub's `defaults.run.shell` precedence, which `check-workflow-pipefail` and `check-runner-var-foreign-shell` both need. `shell_program` reads which program a `shell:` template starts, and it reads it off the bash grammar. `step_span_ends` and `container_block_end` say where a step's opt-out may be written, bounded by the step's own job. `check-failure-only-diagnostics` keeps its behaviour and drops its private copy. `yaml_comment_view` moves there too, so a lint that reads an opt-out out of YAML asks one definition what a comment is.
- `check-workflow-pipefail` no longer misses a step whose interpreter path is quoted. It read the program's name with a whitespace split, so `shell: "/opt/my tools/bash" -e {0}` gave the name `"/opt/my`. That name is in no list of POSIX shells, so the check skipped the step, and a pipe that masks a failure went unreported. `shell_program` keeps the quoted path as one word.
