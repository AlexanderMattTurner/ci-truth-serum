- `check-always-reporter` now accepts a fail-closed twin only when the twin really fails closed. Its `if:` must name exactly the decide gates the workflow declares, it must `needs:` each gate it names, and its last `run:` step must end in a failing command. A twin that named one of two gates, named a job that is no gate, omitted the gate from `needs:`, or ran and exited 0 used to satisfy the check while the merge still greened over a broken gate. The step's shell is read with the bash grammar, so `cmd && exit 1` (which always fails) is separated from `cmd || exit 1` (which does not).
- `check-required-reporter` now demands a `# required-check:` classification on every gated work job in a workflow whose only fail-closed shape is a twin. The twin is skipped on a healthy run, so the work jobs are the check runs branch protection reads there.
- `check-static-concurrency` and `check-pending-cancel-concurrency` now recognize the twin shape as a required-check shape. Both read one shared probe, so neither can judge a twin-shaped workflow differently from the other. A twin-shaped workflow with a static workflow-level concurrency group, or with a ref-keyed group and an extra `pull_request` activity type, is now reported.
- `check-always-reporter` runs the bash grammar, so its `additional_dependencies` now carry `tree-sitter` and `tree-sitter-bash`.
