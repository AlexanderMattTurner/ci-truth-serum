- `check-drift-guards` now follows the DATA when it looks for a copies-agree test, instead of the layout of the file. The structural route used to need the source read and the maintained-copy equality in ONE function body, so two shapes walked past it: a read hoisted to module scope, to a fixture, or to a one-line read accessor; and an equality fanned out over `@pytest.mark.parametrize`, where the hand-kept collection sits in the decorator and each case compares one item. Both are flagged now. Precision is unchanged on this repo: the same 8 findings before and after, and every one of the 235 table-driven parametrize tests stays quiet, because a value that passes through a call to the code under test is no longer treated as the live side. Clear a genuine non-guard with `# not-a-drift-guard: <reason>`, which you may now write on a decorator or in the comment block above the test, not only inside the body.
