- `check-uncached-download` now follows a script behind a launch wrapper. `timeout 900 bash setup.bash`, `sudo bash x.sh` and `env A=1 bash x.sh` all reach the script. Before this change, the walk stopped at the wrapper, so the job passed with no finding. A wrapper that changes directory (`env -C`, `sudo -D`) still ends the walk, because the script is then in a directory that the walk does not track.
- `check-uncached-download` now reads a hash comparison as a digest check, for example `[[ "$(sha256sum <f)" == "$SHA" ]]`. The checksum tool can be a name, an array such as `HASH=(sha256sum)`, or a function that runs one. A comparison against an empty string is not a digest check.
- `check-uncached-download` now reports a call to a function that downloads a file and checks the digest of that file, even when the URL is a value that only the run knows. The check reports the outermost call that carries a pin, because that call names the tool and its version. On agent-glovebox, the fresh-setup job downloaded every pinned Kata asset on each run and passed with no finding.
