- Every check that scans the files you name now refuses a run with no files, instead of reporting a clean pass over nothing. Such a check loops over its arguments, so an empty argument list ran the loop zero times and returned 0 — the exit code of a real pass. A caller that forgot the file list read that as "this repository is clean". The refusal exits 2, which separates a usage error from the 1 that means violations found, and it prints the command that scans the whole tree. All 27 content checks share one entry point now, `run_file_cli`, so the guard cannot be missed by a check added later. Workflow checks are unaffected: they find their own files and never take arguments.
