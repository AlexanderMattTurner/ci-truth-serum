- A check can no longer report a clean pass over files it never scanned. This had two shapes. A check that scans the paths you name looped zero times over an empty argument list and returned 0 — the exit code of a real pass — so a caller who forgot the file list read it as "this repository is clean". All 27 such checks now share one entry point, `run_file_cli`, which refuses an empty run with exit 2 and prints the command that scans the whole tree. A check that finds its own files under `.github/` returned 0 in silence when it found none; exit 0 is honest there, because a repository with no workflow has none to violate, so those say on standard error that they scanned nothing. `check-provenance-repo-url` says the same when the repository has no `origin` remote to compare against.
- The workflow checks share one file-discovery definition again. Nine of them carried a private copy that read the same two globs, and each copy was a place the notice above could go missing. `workflow_files` now takes the composite-action directory as an optional argument, which is the only way the copies differed.
