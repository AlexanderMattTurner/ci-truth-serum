- `check-curl-retry` closed four holes that reported a clean verdict on a download with no working retry. A variable assigned AFTER the curl command no longer credits it, because the shell runs the assignment later. A variable name inside a larger word no longer credits it: `curl "https://example/$retry/$wide" -o f` sends curl one address and no flag. A value the shell computes, such as `OPTS="$(echo --retry 3)"`, credits nothing, because the words come from a program the check cannot run. Each `--next` starts a separate curl operation, and the check now judges every operation on its own, so a widened first download no longer covers a narrow second one.
- `check-curl-retry` reads curl's flags in order. The last spelling of a boolean flag wins, so `--no-retry-all-errors` and `--no-retry-connrefused` turn an earlier widening flag back off.
