- `check-cron-alert-coverage` (Extras): fails a scheduled workflow whose failures reach nobody — a cron has no PR surface, so its red is visible only to whoever opens the Actions tab. By default reports only a malformed `# cron-alert: false  # <reason>` marker and a notification step behind a success-only gate (`if: success()`, `needs.x.result == 'success'`), which reads as coverage but fires never; `--require-alert` additionally demands every scheduled workflow carry a failure-reachable notifier or a reasoned marker, and `--notifier-pattern REGEX` (repeatable) extends the built-in notifier patterns rather than replacing them.
