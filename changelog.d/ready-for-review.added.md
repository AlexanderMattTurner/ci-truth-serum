- `check-ready-for-review` (Tier 1 · Honesty): flags a workflow that gates on the pull request's draft flag and does not list `ready_for_review` in its `pull_request` or `pull_request_target` `types:`. A workflow that skips its jobs while the pull request is a draft has deferred that work, not cancelled it. GitHub reports the pull request leaving draft as the `ready_for_review` activity type, and that type is not in the default set (`opened`, `synchronize`, `reopened`). So the workflow never fires again: the draft run stays the last run, its gated jobs are `skipped`, and GitHub counts a skipped check run as a satisfied required check. The check judges two gate shapes, because a repository can write either. The workflow names `github.event.pull_request.draft` in an `if:`, an `env:` value or a `with:` input. Or a job calls a reusable workflow and passes an input whose NAME carries `draft` — there the gate sits in the callee, so the payload field never appears in the caller at all. On a 50-workflow tree the second shape was 10 of the 18 draft-gated workflows, and a check that read only the payload field would have judged 8 of them. A workflow with no pull request trigger is never judged, so a reusable workflow that holds the gate is silent and its caller is the file reported. Opt out with `# ready-for-review-ok`. Included in the `check-tier1` aggregate.
