- `check-frozen-head-sha` now follows an `env:` variable bound to the frozen head SHA, which it previously did not read at all. It reports only where a step SPENDS that variable in a way the frozen value breaks: as an endpoint of a `git` revision range (`git diff $HEAD_SHA...HEAD`), or as `actions/checkout`'s `ref:`. Those are the two positions the direct rule already banned, so an environment variable is no longer a one-hop route around the check. The binding alone stays clean on purpose: routing an expression through `env:` is the shape the template-injection checks want, and on a 50-workflow tree 41 of the 45 uses of the frozen SHA sat under `env:` with no defect among them. Reading a range endpoint is a question about shell structure, so the `run:` script is parsed with the bash grammar and only a `git` command's own words are judged. A range quoted inside a message that a command prints, or written into a heredoc body, names no `git` command and stays silent. The hook now needs `tree-sitter` and `tree-sitter-bash`, which the aggregates already install.
