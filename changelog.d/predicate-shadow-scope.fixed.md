- `check-test-predicate-shadow` no longer reports clean on the commit that lands the shadow from the production side. A violation is a pair — a test-side definition and a production-side pure predicate — so scanning only the files pre-commit passes missed the case where the production half is what changed: making a shipped function a pure predicate, or renaming one onto a name a long-untouched test file already defines, created the pair with no test file in the file list. The passed list now only ever narrows the scan (a production file in it widens the test side to the whole tree), so the empty-baseline guarantee the check is worth anything for holds on every commit, not only on test-side ones.
