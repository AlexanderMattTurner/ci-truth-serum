- `check-flock-fixed-fd` (Tier 1, honesty): flags `flock <number>`, a lock taken on a hardcoded file descriptor. That number is a name every process in the same descriptor table shares, so a caller, a test harness or a CI wrapper that already holds it owns a different file. The lock then guards nothing, both runs proceed, and the job still reports success. When the descriptor is not open at all, `flock` exits non-zero and a `set -e` caller dies at a line that reads like a lock acquisition. Let the shell allocate one instead: `exec {lock_fd}>FILE`, then `flock -x "$lock_fd"`. A path operand and a computed descriptor both pass. Opt out with `# allow-fixed-fd: <reason>`.
