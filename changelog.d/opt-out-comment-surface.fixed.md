- The lints now read an opt-out marker only from a real comment, as the grammar of the language finds it. Before this fix, a marker in a string that a command prints, in a heredoc body, or in a URL fragment cleared the finding. For example, `echo "to opt out, write # allow-exit-suppress: why"` on the line above `cmd || true` cleared `check-exit-suppression`. The same defect was in `check-soft-timeout`, `check-curl-retry`, `check-pinned-downloads`, `check-bare-mkdir`, `check-echo-fallback`, `check-versionless-install`, `check-truncating-pr-json`, `check-gh-slurp-jq`, `check-secret-file-perms`, `check-stderr-suppression`, `check-stderr-merge-parse`, `check-substitution-exit-swallow`, `check-flag-arity` and the Python lints that read a marker from the raw line.
- In a workflow, a marker in a `run:` value now counts only when it is a shell comment in a step that bash runs. Before this fix, `- run: echo "annotate with # trusted-base-ok: <reason>"` cleared `check-trusted-base`, and the same text with `untrusted-exec-ok` cleared `check-untrusted-exec`. A step whose `shell:` is not bash or sh gives no marker.
- A marker reason that is only a template slot, such as `<reason>` or `<why>`, now clears nothing. The words `n/a`, `none` and `x` now state no reason in every marker, not only in some.
