- `check-curl-retry` now asks for curl's own widened retry on a file-writing `curl … -o <file>` download, and reports two shapes with separate messages. A download with no `--retry` is the first. A download whose `--retry` carries no `--retry-all-errors` and no `--retry-connrefused` is the second: plain `--retry` covers only curl's default transient replies, so a refused or aborted connection (curl exit 56) is never retried. The check resolves a flag the script assigns to a variable, so `widen="--retry-connrefused"` and `OPTS=(--retry 3 --retry-all-errors)` both count. `--retry-delay` alone no longer reads as a retry, because it starts none.
- `check-curl-retry`'s `--retry-wrapper NAME` is **retired**. A caller-side retry wrapper no longer exempts a download. A wrapper restarts the whole command on a sleep schedule somebody picked by hand, and a proxy that aborts every attempt at once burns the whole ladder in seconds. Where a wrapper and `--retry` are both present the two windows multiply. `main()` still accepts the flag and ignores it, so an existing config keeps running; it prints one note telling you to drop the flag.
