- `check-argument-exit-swallow` (Tier 1 · Honesty): flags a command substitution passed as an ARGUMENT — `my_helper "$(risky_listing)"` — in a file that runs under `set -e`. The shell discards the substitution's exit status, so `set -e` reports on the outer command, which succeeds on empty output. This is the sibling of shellcheck's SC2155 (`local x="$(cmd)"`) one syntactic step over, and shellcheck has no rule for it. The check fires only when the outer command is a function that the scanned file, or a file it sources, defines: `echo "$(date)"` and `grep -q "$(f)" file` are idiomatic and are the bulk of the matches, and a call to a function this tree owns is the shape where the author meant the failure to propagate. A source path the shell computes (`source "${SCRIPT_DIR}/lib.sh"`) resolves by its trailing literal name against the tracked shell files. Everything else is a node shape on the bash grammar (`_bash_ast`), so a substitution in a `variable_assignment`, in a `command_name`, in a printed message, or in a heredoc body is out of scope. Opt out with a reason-bearing `# allow-argument-exit: <reason>`. Included in the `check-tier1` aggregate.
