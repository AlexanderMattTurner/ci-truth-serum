- `trace-ci`: a `cd`, `pushd`, `popd` or `make` after `command` or `builtin` (`command cd sub`) now counts as that command. Before this fix, trace-ci did not follow the directory change, and it did not see the `make`. A `command -v` or `command -V` only prints a name, so it counts as no command. A wrapper such as `env command make` runs a program named `command`, so it runs no make.
- `trace-ci`: only bash and zsh have `builtin`, `pushd` and `popd`, and `sh` can be dash. So in a step that another shell runs, trace-ci does not know the directory after one of these commands, and it reports a `make` after it as `untraced`.
- `trace-ci`: a CI `make` call that reads its makefile from its input (`-f -`) is now `untraced`. Each dry run of `make` now gets an empty input. Before this fix, the dry run read the input of trace-ci, so it could stop and wait at a terminal.
