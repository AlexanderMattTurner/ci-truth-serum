- `actions/mute-failure-guard`: a JavaScript action that you add as the first step of a job. It points `BASH_ENV` at a guard that records every failed bash command in a ledger, with its file, line, status and command text. The guard records a failure that an outer command drops, such as `f "$(g)"`. When the job fails, the action prints the last 50 ledger rows, the failed step's status and signal, `ulimit -n`, the open-file count and the process count. A failed step that printed no error text gets its own `mute failure` error. Bash runs no ERR trap inside a condition, so a failure there is not in the ledger.
- `check-mute-guard` (honesty, enabled on its own, outside the tier aggregates): the check requires the guard action before the first bash `run:` step of each job. `--only <glob>` limits it to the workflows you name. Opt out with `# allow-unguarded-job: <reason>`.
