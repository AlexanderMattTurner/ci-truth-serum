- `check-sparse-checkout-closure` now counts the files a job's closure OPENS at run time, declared with a `sparse-checkout-needs: <path> [<path>…]` comment. An `import` and a `source` are the only two references the check can follow. A module that stats a config file, or reads a template, writes neither, so the file stayed invisible and the job died on the runner with `cannot find the repository root`. The declaration goes in the file that opens the path, and every job that EXECUTES that file must then serve the path. A job that merely names the file, as `ruff check` does, runs nothing in it and owes nothing it opens. Everything after the colon is a path, so a reason on that line reads as one and fails. The check reads the declaration from a real comment, through the language's own grammar, so the same words inside a string literal declare nothing. A declaration may name a directory, and each tracked file inside it must then be served. The scan runs to a fixed point, so a declared file that declares in turn — a launcher that names its plugin, a plugin that names its config — is followed to the end. Each path is repo-relative, and a path that names no tracked file is now a violation: sparse-checkout serves tracked files alone, so a typo there widens nothing and used to say nothing. The derivation only ADDs dependencies, so it can turn a passing job red and can never green a broken one; a closure that declares nothing is judged exactly as before.
