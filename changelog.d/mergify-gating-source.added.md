- **`check-cancellable-required-check`, `check-pending-cancel-concurrency` and `check-required-event-closure`** now read the gating checks from a Mergify config as well as from the `# required-check: true` markers. A repository that moved to Mergify and deleted its markers got no finding from these checks, because they found no gate to judge. A job now gates when a queue rule names its check in `check-success=<name>`. The checks read `.mergify.yml`, `.mergify/config.yml` or `.github/mergify.yml`, the first that exists. A job gates through `queue_conditions`, through `merge_conditions`, or through the `conditions` of a `pull_request_rules` entry with a `queue` action. Each one gates on every pull request event. A Mergify gate does not need a `merge_group` trigger. Each check takes `--gating-source=markers|mergify|both`, and the default is `both`. A config that the checks cannot read without a guess, such as one with `not:` or `extends`, is now a hard error. Pass `--gating-source=markers` to ignore it.
