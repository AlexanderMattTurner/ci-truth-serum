- **`check-wall-clock-assertions`** now flags a Python `assert` that compares two measured durations, such as `assert min(fast) < 1.6 * min(slow)`. A loaded runner stretches each duration by a different amount, so the order between them measures the runner. The check follows durations that `append` collects into a list, or into a list that a dict holds (`taken[which].append(...)`). It reads that list through `min`, `max`, `sum`, the `statistics` averages, `sorted` and a subscript. It also follows a total that `+=` builds from durations. A bare clock reading is no longer a duration, so `assert start > 0` is clean, and `assert first_seen < second_seen` stays clean. The `allow-wall-clock: <reason>` opt-out does not change. The JavaScript and TypeScript arm does not compare two durations yet.
