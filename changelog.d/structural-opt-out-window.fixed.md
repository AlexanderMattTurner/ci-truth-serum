- An opt-out comment at the end of a code line now covers only the construct that line opens. Before, it also covered the next line. So `- macos-latest  # allow-…: why` cleared an unmarked `- ubuntu-latest` below it, and `echo a  # allow-…` cleared the command below it. Each language's own parser now decides which lines open a construct: `if  # pin-exempt: …` still covers the `curl` below it, `key:  # …` covers its value, and `>- # …` covers its block scalar. A marker that relied on the old rule moves onto the finding's line, or into a comment block above it.
